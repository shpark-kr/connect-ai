# 📝 CEO 종합 보고서

🎨 Designer: 작업 시작합니다.

CEO님의 지시에 따라 'Critical Failure' 콘셉트를 모든 콘텐츠에 일관성 있게 적용할 수 있는 **시스템 경고/글리치 에셋 키트(System Alert/Glitch Asset Kit)**를 설계했습니다. 이 키트는 시각적, 청각적 요소를 통합하여 공학적 위기감과 전문적 권위를 동시에 극대화하는 데 초점을 맞췄습니다.

이 가이드라인은 모든 콘텐츠 제작자가 단일한 시스템을 사용하도록 강제하며, 단순 에셋 제공에 그치지 않고 **사용법(Usage Flow)**까지 정의합니다.

---

## 💾 온현 (Onhyun) - System Alert Asset Kit v1.0
**목표:** 콘텐츠 전반의 긴급성(Urgency)과 전문적 권위(Authority) 동시 확보.
**톤앤매너:** 클리니컬, 시스템 경고 인터페이스, 공학적 오류 메시지.

### 🎨 섹션 1: 비주얼 컴포넌트 (Visual Components)

#### 1. 핵심 컬러 팔레트 정의 (Color Palette)
| 역할 | 명칭 | HEX 코드 | 사용 목적 및 가이드라인 |
| :--- | :--- | :--- | :--- |
| **메인 배경** | System Base Black | `#0A0D13` | 모든 시스템 경고/진단 화면의 기본 배경색. 어둡지만 검은색보다는 톤이 높은 블랙으로 전문성을 유지. |
| **주요 텍스트** | Primary Text White | `#E6E8F0` | 핵심 정보 및 본문 텍스트 색상. 명확한 가독성 최우선. |
| **위험 경고색** | Deep Crimson Red | `#B71C1C` | (Critical Failure) 가장 위험도가 높은 지점, 실패 메시지(Failure Message), CTA의 최종 경고 버튼 배경. *사용 빈도 제한.* |
| **주의/경고색** | Warning Amber | `#FFC107` | 시스템에 문제가 생길 '가능성'이 있는 부분, 낮은 수치 구간 표시, 플래시 효과 강조. |
| **전문 정보색** | Authority Blue | `#4A90E2` | 정상 범위 안내, 해결책(Solution) 제시 부분의 긍정적 정보 제공. (Deep Crimson Red와 명확히 대비되도록 사용). |

#### 2. 타이포그래피 시스템 (Typography System)
*   **헤드라인/제목:** `Oswald` 또는 `Bebas Neue` (Bold, All Caps 권장): 공학적인 긴급함과 시인성을 극대화합니다.
*   **본문/데이터:** `Roboto Mono` 또는 `Courier New`: 코드를 나타내는 모노스페이스 폰트 사용을 의무화하여 '시스템 로그' 같은 느낌을 부여합니다.

#### 3. E-XXX 글리치 에셋 (Glitch Effect Asset)
*   **기능:** 시각적 불안정성(Visual Instability) 조성 및 정보의 신뢰도를 일시적으로 하락시키며 긴급성을 고조.
*   **기술 스펙:**
    *   **애니메이션 유형:** Chromatic Aberration (색상 분리) + Horizontal Jittering (수평 떨림).
    *   **실행 주기:** 0.1초 ~ 0.3초 간격의 깜빡임(Flash)이 반복되어야 합니다.
    *   **디자인 컴포넌트:**
        1.  `[GLITCH_FRAME]`: 가장 기본 형태. 화면 전체 또는 특정 코드 블록을 덮으며, RGB 채널을 분리(Red-Cyan-Blue 3개 레이어)시키고 수평으로 미세하게 떨립니다.
        2.  `[SCANLINE]`: 전역적으로 적용 가능한 가느다란 사선 패턴. 배경 위에 오버레이 되어 '디지털 모니터' 느낌을 강조합니다. (주기: 15~20px 간격).
*   **사용 원칙:** 글리치 효과는 **최대 3회 이내**로 제한하며, 반드시 중요한 정보(예: Defect ID)가 깜빡일 때만 사용해야 합니다.

#### 4. 시스템 알림 오버레이 (System Alert Overlay - The Core Component)
*   **디자인 역할:** 화면의 특정 영역을 '공식 진단 결과'처럼 보이게 만듭니다.
*   **구성 요소 및 배치:**
    1.  **알림 바(Header):** 상단에 고정되며, `[SYSTEM ALERT]` 텍스트가 **Warning Amber**로 깜빡입니다. (좌측 정렬)
    2.  **Defect ID 블록:** 가장 크게 표시됩니다. 예: `<E-403>` - Deep Crimson Red 배경에 모노스페이스 폰트 사용. 전역적으로 최우선으로 노출되어야 함을 시각화합니다.
    3.  **문제 요약 박스 (Summary):** 글리치 효과가 적용된 작은 텍스트 블록 내에, 문제의 핵심(예: "관절 불안정성 위험도 급증")이 표시됩니다.
    4.  **액션 유도 버튼 (CTA Anchor):** 항상 하단 중앙에 위치하며, `[진단 결과 확인하기]` 등 명확한 문구와 함께 Deep Crimson Red 배경으로 배치합니다.

### 🎧 섹션 2: 사운드 스펙 및 SFX 가이드라인 (Audio Components)

사운드는 시청자의 **주의력**과 **긴급성**을 물리적으로 자극하는 장치입니다. 음악(BGM)은 항상 낮은 볼륨의 불안정한 전자음 또는 심장 박동 소리를 깔아 놓는 것이 기본이며, 아래 SFX를 이벤트 발생 시점에 배치해야 합니다.

| 상황/이벤트 | 추천 SFX 유형 (SFX ID) | 사용 목적 및 타이밍 |
| :--- | :--- | :--- |
| **진단 시작** | `[BEEP_LOW]` 또는 `[SCANNER_INIT]` | 진단 과정의 시작 시점. 낮은 주파수의 톤으로 전문적인 느낌 부여. |
| **경고 발생 (Warning)** | `[ALERT_TONE]` / 짧은 사이렌 소리 | Defect ID가 처음 화면에 등장하거나, 수치가 위험 수준을 넘어설 때. (너무 크지 않게 주의). |
| **최대 위기 경보** | `[CRITICAL_FAILURE]` / 딥 와우(Deep Whoosh) 사운드 | 가장 결정적인 문제점 제시 시점, 또는 MiniFunnel 진입 직전의 클라이맥스 부분. (청취자가 '멈칫'하게 만드는 강한 충격). |
| **정보 전달/슬라이딩** | `[DATA_SWIPE]` / 부드러운 전자음 | 그래프나 데이터를 전환할 때 사용하며, 정보 흐름을 매끄럽게 연결함. (긴장감을 해소하지 않도록 주의). |

### ⚙️ 섹션 3: 콘텐츠 적용 가이드라인 및 요약 (Implementation Guidelines)

| 항목 | 규칙/제한 사항 | 제작자 체크리스트 |
| :--- | :--- | :--- |
| **일관성** | 모든 에셋은 다크 네이비 계열 배경과 모노스페이스 폰트를 유지해야 합니다. 색상 사용은 위 정의된 팔레트(특히 Red, Amber)에 철저히 구속합니다. | ✅ 모든 비주얼 요소가 Deep Crimson Red/Warning Amber 중 하나를 통해 '위험'을 강조하는가? |
| **글리치 제어** | 글리치는 *정보의 중요성*과 비례해야 합니다. 단순 장식으로 사용하지 마십시오. (예: Defect ID가 제시될 때만 사용) | ✅ 글리치가 너무 잦아 콘텐츠 자체의 메시지를 흐리지 않는가? |
| **사운드 조화** | SFX는 배경음악(BGM)을 압도해서는 안 되며, BGM과 '대비'를 이루어 이벤트의 순간적인 임팩트만 높여야 합니다. | ✅ 사운드의 피크 지점이 시청자의 주의가 가장 높은 핵심 정보 전달 타이밍인가? |
| **CTA 연결** | 모든 시스템 경고 과정은 궁극적으로 `[액션 유도 버튼]`을 향해야 하며, 이 버튼은 항상 '오류 해결'이라는 관점으로 포장되어야 합니다. | ✅ 콘텐츠의 마지막 10%는 반드시 진단 결과 및 다음 액션을 제시하는가? |
