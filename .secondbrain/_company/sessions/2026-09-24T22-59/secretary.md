## 📌 I. 코다리 테스트 기반 발견된 시스템 취약점 (Bug Report)

코다리의 스트레스 테스트 결과, 기존 구조는 다음과 같은 근본적인 아키텍처적 약점을 가지고 있었습니다.

1.  **[취약점 A] API 호출의 단일 실패 지점 (SPOF):**
    *   **문제:** 외부 서비스(예: 네이버 Open API, 공공데이터 API)에 대한 요청이 한 번 실패하면 전체 파이프라인이 멈춥니다. 재시도 로직 부재로 인해 일시적인 네트워크 문제에도 콘텐츠 발행 자체가 중단됩니다.
    *   **해결책:** `ResilientAPIClient` 패턴 의무 적용. 모든 외부 API 호출은 반드시 **지수 백오프(Exponential Backoff)**와 **Circuit Breaker**를 거쳐야 합니다. (재시도 횟수 및 임계값 설정 필수)

2.  **[취약점 B] 데이터 구조화의 불일치:**
    *   **문제:** 콘텐츠에 사용되는 정책 정보가 단순 원문 보고서 형태로 존재하여, 여러 플랫폼(유튜브 설명란/블로그 본문 등)에서 일관된 포맷으로 재활용하기 어렵습니다. (정보 추출 및 가공 과정에서 오류 발생 위험 높음)
    *   **해결책:** 모든 공공 정책 데이터는 **마스터 DB 구조화 원칙**을 따릅니다. (데이터 필드 정의: *키워드*, *핵심 수치*, *타깃 혜택*, *적용 대상*, *신청 경로* 등)

3.  **[취약점 C] Funnel CTA의 비표준성:**
    *   **문제:** 콘텐츠 플랫폼(유튜브, 블로그, 인스타)마다 Call To Action (CTA)의 디자인과 문구가 달라 시각적 일관성이 떨어지고, 전환 경로가 분산됩니다.
    *   **해결책:** `Funnel CTA Master Component Set`을 **모든 산출물에 강제 삽입**합니다. 이 컴포넌트가 가장 최신 버전이며, 모든 플랫폼에서 동일한 메시지를 전달해야 합니다.

## 📋 II. 콘텐츠 발행 전 최종 검증 체크리스트 (Mandatory Checklist)

새로운 콘텐츠를 어떤 형태로든 발행하기 직전에는 아래 6가지 항목을 반드시 점검하고 기록해야 합니다. 이 중 하나라도 누락되면 발행이 보류됩니다.

| No. | 필수 검증 영역 | 세부 확인 사항 (Pass/Fail) | 담당 에이전트 |
| :---: | :--- | :--- | :--- |
| **1** | **팩트체크 및 신뢰성** | 🚨 모든 정책 데이터 출처가 '공식 공공데이터'와 일치하는가? (출처 명시 필수) | Researcher |
| **2** | **플랫폼 최적화** | 🎬 각 플랫폼(쇼츠/릴스/클립 등)의 길이, 포맷, 후킹 구조에 맞게 분할되었는가? | Writer / Leo |
| **3** | **전환 경로 (Funnel)** | 🔗 콘텐츠 내에서 다음 단계 액션(CTA)이 명확하고 매끄럽게 연결되는가? (예: 영상 시청 → 설명란 리드 마그넷 다운로드 유도) | Designer / CEO |
| **4** | **기술적 안정성** | 🛠️ API 호출 로직에 지수 백오프 및 Circuit Breaker 패턴이 적용되어 있는가? (시스템 레벨 검토) | Developer |
| **5** | **시각/브랜드 통일성** | ✨ 모든 산출물(썸네일, 자막 등)에 노랑/흰색 고대비 모듈형 에셋과 브랜드 톤이 일관되게 적용되었는가? | Designer |
| **6** | **최종 승인 및 보고** | ✅ 최종 브리핑 자료(산출물 목록, KPI 예상치, 발행 일정)에 CEO의 검토 서명이 완료되었는가? | Secretary (영숙) |

'공공 데이터 기반의 핵심 정책 주제를 Funnel 구조에 맞게 재정의하고, 이를 바탕으로 첫 번째 고수익 콘텐츠 패키지를 완성하는 것.' (리서처와 라이터를 통한 **콘텐츠 기획-원고 초안 확정** 단계)

이는 단순히 스크립트를 쓰는 것이 아니라, **'어떤 정보를 어떤 순서로 배치해야 가장 많은 관심을 받고 다음 행동으로 유도할지'**를 구조적으로 설계하는 작업입니다.

**🛠️ 에이전트 분배:**
1.  **Researcher (리서처):** 🎯 역할 재정의 및 마스터 DB 구축 완료 후, **가장 시장성 높은 공공데이터 주제 3가지**를 선정하고, 각 주제에 대한 Funnel 전환 지점을 명확히 정의해야 합니다. (예: '주제 A' → 'Pain Point 인식' → '우리 서비스/상품 필요성 인지')
2.  **Writer (작가):** 리서처가 제시한 3가지 주제의 **핵심 페인 포인트(Pain Point)에 기반한 초안 구조 설계**를 시작해야 합니다. 이 단계에서 모든 콘텐츠 에이전트들이 참고할 '마스터 브리프' 스타일의 Out-line을 작성하는 것이 목표입니다.
