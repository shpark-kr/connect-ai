## 📄 [통합 브리핑 문서] MiniFunnel 시스템 복구 프로토콜 v1.0
**수신:** 개발팀 (Developer)
**작성일:** 2026-09-30
**목표:** 콘텐츠 시청자의 불안감을 자극하고, 공학적 진단 과정을 거치게 하여 MiniFunnel의 최종 제품(진단 페이지)로 유도하는 인터랙티브 웹 경험 구축.

### 🎯 I. 핵심 목표 및 사용자 흐름 (User Flow Map)

| 단계 | 역할/페이지 | 목적/사용자 감정 | 데이터 입력/출력 |
| :--- | :--- | :--- | :--- |
| **1. 유입** | 콘텐츠 플랫폼 (릴스, 유튜브) | 문제 인식 / 위기감 조성 (Failure Injection) | *Trigger:* E-XXX Defect ID 노출, 경고음 삽입 |
| **2. 진단 시작** | MiniFunnel 랜딩 페이지 (System Alert) | 호기심/긴급성 증가 → '진짜 알아야 한다'는 압박감 | *Input:* 사용자가 느끼는 증상(클릭 기반 선택지) |
| **3. 핵심 프로세스** | State Machine Logic (프로토콜 시뮬레이션) | 전문적 분석 경험 제공 (권위 확보) | *Data Flow:* Step 1 → Step 2 → ... → Final Defect ID 도출 |
| **4. 전환/최종 액션** | 복구 프로토콜 페이지 (Recovery Protocol) | '해결책'에 대한 갈망 극대화 (Pain Point 해소 시점) | *Output:* 최종 진단 결과(예: E-M411 확정), CTA 노출 |
| **5. 목표 도달** | MiniFunnel 상세 진단 페이지 | 해결책 구매 고려 (전환 완료) | - |

### ⚙️ II. 컴포넌트별 기술 스펙 및 데이터 흐름 (State Machine Logic)

개발팀은 아래의 세 가지 핵심 자산(Asset)을 중심으로 인터랙티브 상태 기계를 구축해야 합니다.

#### 1. [A] 초기 위기감 조성 모듈 (System Alert Module)
*   **역할:** 사용자를 페이지에 붙잡아 두는 도입부 경고 시스템.
*   **스펙:** Deep Crimson Red 테마 기반의 고화질 비주얼 에셋 필수. 공학적 오류 코드(E-XXX, M-411 등)를 반드시 시각적으로 보여줄 것.
*   **상태 전환 조건 (State Transition):**
    *   `Initial State (Default)` → 사용자가 첫 번째 질문에 '관련 있음'을 클릭할 때 (`Input: Yes`) → `Diagnostic Step 1 State`.

#### 2. [B] 진단 과정 로직 모듈 (Core Diagnostic Engine)
*   **역할:** 단순 페이지 이동이 아닌, 데이터가 누적되며 상태가 변하는 시뮬레이션 경험 제공.
*   **데이터 흐름:**
    1.  **Input Layer:** 사용자가 릴스/콘텐츠에서 본 Pain Point와 가장 근접한 질문에 답함 (예: "아침에 무릎이 불편하신 적이 있나요?").
    2.  **Processing:** 내부 로직(가정)을 거쳐, 현재 증상 데이터를 가공하여 `Defect ID`를 임시 생성/갱신합니다.
    3.  **Output Layer:** 다음 단계로 넘어갈 때마다 "현재 시스템은 [데이터 손실] 상태입니다. 추가 검증이 필요합니다."와 같은 공학적 코멘트를 제공해야 함.

#### 3. [C] 최종 확정 및 CTA 모듈 (Recovery Protocol & Funnel)
*   **역할:** 진단 과정을 마무리하고, 문제의 심각성을 최고조로 끌어올려 '해결책'을 강하게 제시하는 단계.
*   **스펙:** 시스템 복구 프로토콜 UI 컴포넌트(애니메이션 포함)를 사용해야 함. 최종적으로 도출된 Defect ID에 대한 전문적인 설명을 덧붙여야 합니다.
*   **최종 상태 전환 조건:**
    *   `Diagnostic Step N State` → 모든 필수 질문 완료 및 `Final Defect ID (E-M411)`가 확정될 때.
    *   → **Action:** "시스템 복구 프로토콜을 실행해야 합니다." 메시지 노출 및 MiniFunnel 링크 버튼 활성화.

### 📝 III. 개발팀 액션 아이템 요약 (Checklist)

*   [ ] **데이터 구조 정의:** 모든 질문과 답변에 대한 가중치와 Defect ID 매핑 로직을 백엔드에서 명확히 구축할 것.
*   [ ] **UI 컴포넌트 통합:** A, B, C의 세 가지 UI 스펙(딥 크림슨, 경고문구, 복구 프로토콜)이 끊김 없이 연결되도록 애니메이션 흐름을 설계할 것.
*   [ ] **QA 우선순위:** '시스템 오류'가 발생했을 때 사용자에게 보여야 할 메시지와 로직을 최우선으로 테스트해야 합니다. (Failure Injection Test)
