### 🎨 1. 공통 디자인 시스템 및 컴포넌트 스펙

#### A. 컬러 팔레트 (Color Palette)
| 이름 | Hex Code | 용도 | Notes |
| :--- | :--- | :--- | :--- |
| **Primary Yellow** | `#FFC300` | CTA 버튼, 강조 문구, 경고 아이콘 | 시니어에게 눈에 띄는 고대비 메인 액션 컬러. |
| **White/Background** | `#FFFFFF` | 배경, 본문 텍스트 영역 | 최고 가독성 확보. |
| **Dark Navy/Text** | `#2C3E50` | 본문 텍스트, 제목 (높은 전문성 부여) | 일반 블랙보다 부드럽지만 강한 대비를 유지. |
| **Error State** | `#D9534F` | 필수 입력 누락, 유효성 검사 실패 메시지 | 명확하고 직관적인 경고색. |
| **Success State** | `#5CB85C` | 결제 성공, 다운로드 완료 메시지 | 긍정적이고 안정적인 피드백 컬러. |

#### B. 타이포그래피 (Typography)
*   **폰트:** Noto Sans KR 또는 Spoqa Han Sans Neo (가독성 최우선).
*   **본문 크기:** 최소 `18px` 이상 유지 (모바일 및 데스크톱 공통).
*   **CTA 텍스트:** 볼드(Bold) 처리, 제목과 동일한 색상 대비를 유지.

### 🧱 2. 핵심 컴포넌트 상세 스펙: Paywall Modal

이 모달은 무료 콘텐츠 마지막에 등장하여 사용자의 '정보 부족'을 자극하고 결제를 유도하는 역할을 합니다.

| 요소 | 스펙 정의 (Props/State) | 디자인 가이드라인 |
| :--- | :--- | :--- |
| **Trigger** | `[무료 콘텐츠 끝] $\rightarrow$ [클릭]` | 모달은 전체 화면을 덮는 형태로, 뒤 배경 콘텐츠를 어둡게 처리하여 집중도를 높임. |
| **Headline (H2)** | *Props:* `{ 문제의 핵심 결과적 손실액 }` <br>예: "아직도 이 지원금을 모르고 계신가요? 평균 $XX만원을 놓치셨습니다." | 노랑/흰색 대비를 극대화하여 '경고'와 '위기감'을 조성. 감정적인 자극에 초점. |
| **Body Text** | *Props:* `{ 리포트의 가치 3가지 목록 }` <br>1. A정책과 B정책의 결정적 차이점 비교 (수익률, 조건 등)<br>2. 놓치는 경우 발생하는 재정적 손실 시뮬레이션<br>3. 전문가가 선별한 최신 업데이트 정보 | 복잡한 텍스트를 **불렛 포인트**로 분해하고, 각 포인트를 아이콘(💡)과 함께 강조하여 스캔 용이성을 높임. |
| **CTA 버튼 (Primary)** | *Props:* `onClick={openSubscriptionForm}` <br>`Disabled={false}` / `Label: '🔥 맞춤형 리포트 즉시 다운로드 (유료)'` | 크기는 매우 크게(Full-width), 배경색은 `#FFC300`. 마우스를 올렸을 때(Hover)는 밝은 노랑에서 주황빛으로 미세하게 변하여 반응성을 보여줌. |

### 🔒 3. 핵심 컴포넌트 상세 스펙: Subscription Form (결제 및 정보 수집 양식)

사용자가 자신의 정보를 입력하고 결제를 시도하는 가장 민감한 구간입니다. 모든 에러 핸들링이 중요합니다.

#### A. 기본 구조
*   **레이아웃:** 2단계 진행 방식 채택 (Step 1: 정보 입력 $\rightarrow$ Step 2: 결제 완료).
*   **데이터 필드:** Name, Email (필수), Phone Number (선호/옵션).

#### B. 컴포넌트 상태 정의 (State Machine)

| State | 시각적 변화 (UI/UX) | 시스템 로직 및 피드백 | 개발자 노트 (Props) |
| :--- | :--- | :--- | :--- |
| **Initial** | 모든 필드가 비어 있고, '다음 단계' 버튼은 비활성화(`disabled`) 상태. | 사용자 입력에 따라 실시간 유효성 검사(Validation)를 실행한다. | `is_valid: boolean` (모든 필드 채우기) |
| **Error** | 필수 필드 옆에 작은 텍스트로 에러 메시지 표시 (`${필드명}는 반드시 입력해야 합니다.`) | 사용자가 잘못된 포맷(예: 이메일 주소 형식이 아님)을 입력할 경우 즉시 발생. `Focus`를 해당 필드로 이동시킨다. | `error_message: string` (에러 텍스트 노출) |
| **Success (Input)** | 모든 정보가 채워지고 유효성 검사를 통과했을 때만 '다음 단계' 버튼 활성화. | 백엔드 서버로 데이터 전송을 시도하며, 로딩 스피너(Spinner)를 보여준다. `Loading` 상태임을 명시. | `isLoading: boolean` (스피너 표시) |
| **Paywall** | 결제 정보를 입력하는 별도의 팝업/섹션이 나타난다. (카드 번호 등) | *실제 결제가 이루어지는 최종 단계.* 이탈을 막기 위해 '결제 취소' 버튼은 매우 눈에 잘 띄게 배치한다. | `payment_method: string` (PG사 연동 로직) |

### ✅ 4. 핵심 컴포넌트 상세 스펙: Download Success Page (성공 페이지)

단순히 "다운로드 완료"로 끝나는 것이 아니라, 다음 구매를 유도하거나 데이터베이스에 사용자를 붙잡아두는(Retention) 역할을 해야 합니다.

| 요소 | 스펙 정의 (Props/State) | 디자인 가이드라인 |
| :--- | :--- | :--- |
| **Status Message** | *Props:* `{ '성공적으로 리포트를 다운로드하셨습니다!' }` | 배경은 #5CB85C(Success Color)를 활용한 부드러운 그라데이션. 사용자에게 긍정적이고 안도감을 주는 메시지 톤앤매너 유지. |
| **Download Link** | `href="/download/report_xxxxxx"` | 다운로드 링크는 버튼 형태로 제공하되, '다시 다운로드'가 아닌 '지금 확인하기' 같은 능동적인 문구를 사용한다. (24시간 유효함 강조) |
| **Retention CTA 1 (최우선)** | *Props:* `{ 다음 단계의 가치 제안 }` <br>예: "✅ [무료] 놓친 지원금 체크리스트 PDF 받기" | 이 페이지에 머문 사용자는 '정보를 얻고 싶다'는 상태이므로, 가장 쉽고 빠르게 추가 가치를 제공하는 **'미끼(Lead Magnet)'** 다운로드를 유도해야 한다. (이메일 재수집 기회) |
| **Retention CTA 2 (보조)** | *Props:* `{ 블로그/채널 구독 링크 }` <br>예: "더 많은 최신 정책 정보는 온현 채널을 구독하세요." | YouTube/블로그 아이콘과 함께 배치하여 다음 트래픽 경로를 확보한다. |

***
**[최종 점검 사항]**
1.  모든 상태 전환(State Change)에 대한 명확한 시각적 피드백(로딩 스피너, 에러 메시지 등)이 정의되었습니다.
2.  노랑/흰색 고대비 원칙과 시니어 친화적 가독성을 모든 컴포넌트에서 일관되게 적용했습니다.
3.  단순 기능 구현을 넘어, 각 단계별로 **비즈니스 목표(데이터 수집 및 다음 구매 유도)**를 달성할 수 있는 CTA가 배치되었습니다.
