### 🚨 [최종] Deep Crimson Red 경고 시스템 UX/애니메이션 상세 브리프 (V3.0)

**적용 범위:** MiniFunnel Funnel 전체 State Transition 지점 ($ \to $ ERROR\_DETECTED)
**목표:** 시각적으로 압도적인 위기감을 조성하여, 사용자의 **'개인 데이터 오류 인식(Error Recognition)'**을 유발하고 즉시 해결책(Recovery State)으로 이동하도록 강제한다.

#### 1. Deep Crimson Red의 역할 및 애니메이션 사양 (The Shock Factor)

| 요소 | 디자인 스펙 | 기술 구현 지침 (코다리/개발팀 대상) |
| :--- | :--- | :--- |
| **메인 경고 배경** | **Deep Crimson Red (#8B0000)**을 메인으로 사용하되, 순색(Pure Color)이 아닌 *미묘하게 어두운 톤*의 붉은색 계열로 지정하여 시각적 피로도를 낮추면서도 위압감을 유지한다. | 배경 전환 시 단순한 `opacity: 1` 방식 금지. **Pulse Effect** (0.5초 주기, 강도가 미세하게 커졌다 작아지는 효과)를 적용하여 '시스템 이상 작동' 느낌을 부여해야 함. |
| **텍스트/에러 코드** | **Soft Gold (#FFD700)** 또는 대비가 가장 높은 순백색(Off-White: `#E0E0E0`)을 사용한다. 폰트 크기는 메인 콘텐츠의 최대 1.5배 이상으로 크게 배치하여 공포 메시지의 중요도를 극대화한다. | **글리치 효과 (Glitch Effect)** 적용 필수. 에러 코드가 출력될 때, 짧게(50ms) 화면이 수평/수직으로 번지거나 떨리는(`skew` 또는 `translate`) 애니메이션을 주어 '시스템 오류'의 현실감을 부여한다. |
| **애니메이션 시퀀스** | 경고 진입 $\to$ (1단계: 사운드+배경 변색) $\to$ (2단계: 글리치 효과와 메시지 출력) $\to$ (3단계: 집중 유도 및 CTA 배치). 이 모든 과정은 **최대 4초 내에 완료**되어야 한다. | 경고 진입 시, 배경 전체가 부드럽게(Smooth Ease-out) Deep Crimson Red로 전환되면서, 기존의 모든 요소(네비게이션, 하단 콘텐츠 등)는 동시에 `opacity: 0.2` 수준으로 **자동 비활성화/딤 처리**되어야 한다. (Visual Focus Lock Down). |

#### 2. 시각적 계층 구조 (Visual Hierarchy Check)

현재 테스트 환경에서 가장 자주 발견되는 문제는 '경고 메시지'와 '사용자 이름/데이터 정보' 간의 시각적 경쟁입니다.

*   **문제 지점:** 에러 코드가 표시될 때, 주변의 작은 데이터 항목(예: `Current Index Value`)이 여전히 밝은 색상으로 빛나면서 경고 메시지의 집중도를 분산시킵니다.
*   **수정 브리프:** Deep Crimson Red가 활성화되는 순간, **경고와 직접적으로 관련 없는 모든 보조 정보 요소는 반드시 회색 계열로 톤다운(Gray Scale Dimming)되어야 합니다.** 이는 사용자의 시선이 오직 '위기 메시지'와 '해결책 제시 영역'에만 머물도록 유도하는 핵심 장치입니다.

#### 3. Micro-Animation 브리핑 (미세 조정 지점)

| 구간 | 문제 발생 가능성 | 제안하는 애니메이션 수정 | 개발팀 전달 내용 |
| :--- | :--- | :--- | :--- |
| **Funnel 진입 시** | 너무 갑작스러운 색상 변화로 사용자 경험이 저해될 수 있음. | Deep Crimson Red로 전환되는 시작 지점(Transition Point)에 `ease-in-out`의 부드러운 가속도를 추가하여, 충격적이면서도 세련된 느낌을 준다. | CSS Transition Property 수정 필요: `transition: background 0.7s cubic-bezier(0.42, 0, 1, 1)`와 같이 명확한 커브베지아 함수를 적용할 것. |
| **에러 코드 출력** | 코드가 한 번에 나타나면 공포감이 분산됨. | 에러 레벨(`L1` $\to$ `L2` $\to$ `L3`)별로 텍스트가 타이핑되듯(Typewriter Effect) 순차적으로 등장하게 하여, 마치 시스템이 '진단하는 과정'처럼 느껴지게 한다. | 애니메이션 지연 시간(Delay Time)을 Level 당 최소 150ms 간격으로 설정하여 긴장감을 유지할 것. |
| **CTA 활성화** | 경고가 끝난 후 CTA 버튼의 등장 타이밍이 너무 느릴 수 있음. | Deep Crimson Red의 강한 위기감에서 벗어나 (Red $\to$ Gold), 해결책(Solution)을 제시하는 순간, CTA 버튼은 **Spring Bounce Effect**를 적용하여 '탈출구'로서 즉각적이고 강력하게 느껴지도록 한다. | 트랜지션 아웃 시, `keyframes`를 활용한 물리 기반 애니메이션(`spring`) 구현 요청. |
