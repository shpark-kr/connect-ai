## 📄 Gap Widget API 기술 사양서 (v1.0)
**작성 목적:** 공공데이터 연동 위젯의 데이터 무결성 및 사용자 경험(UX) 신뢰도 확보.
**대상:** 코다리 (개발자), Designer (UI/UX 검증)

### 1. JSON Schema 정의 및 구조화

위젯이 처리해야 할 핵심 데이터는 '개인 상황'과 '공적 제도 상의 Gap 리스크 수치'입니다. 아래 스키마를 준수하여 백엔드에서 최종 데이터를 가공하고 프론트엔드로 전송해야 합니다. (필드는 모두 **선택 사항**으로 간주하고, 부재 시 예외 처리를 해야 함)

| 필드명 | 데이터 타입 | 필수 여부 | 설명 및 제약 조건 | 예시 값 |
| :--- | :--- | :--- | :--- | :--- |
| `status_code` | String | O | API 호출 성공/실패 상태 코드 (e.g., "SUCCESS", "FAILURE") | SUCCESS |
| `timestamp` | String | O | 데이터 최종 조회 시각 (ISO 8601 형식) | 2026-09-24T10:30:00Z |
| `risk_data` | Object | X | 재정적 리스크 요약 객체. | { ... } |
| `risk_data.gap_score` | Number | X | 핵심 Gap 점수 (0~100점). 높을수록 위험함. | 78.5 |
| `risk_data.loss_potential` | Number | X | 미활용 자원/혜택의 추정 금액 (단위: 원). | 3,500,000 |
| `risk_data.top_gap_area` | String | X | 가장 큰 재정적 손실이 발생하는 분야 요약. | 노인 장기요양보험 급여 외 항목 |
| `detail_info` | Array | X | 근거가 되는 공공 제도 정보 목록 (최대 3개). | [ { ... }, { ... } ] |
| `detail_info[].benefit_name` | String | O | 해당 제도의 정식 명칭. | 국민연금 기초 수급자 지원 |
| `detail_info[].legal_basis` | String | O | 법적 근거 조항 및 출처 (신뢰도 확보 필수). | 국민기초생활 보장법 제XX조 |
| `detail_info[].description` | String | X | 해당 혜택의 핵심 설명. | 수급권자에게 제공되는 기본적인 생계 지원... |

### 2. 예외 케이스 처리 프로토콜 (Error Handling Protocol)

단순히 데이터가 없다고 처리해서는 안 됩니다. **왜** 데이터가 없는지, 그리고 사용자에게 **무엇을 해야 하는지**를 명확하게 안내해야 합니다.

| No. | 예상되는 문제/예외 케이스 | 발생 원인 | 클라이언트(프론트) 동작 지침 | 서버(백엔드) 응답 JSON 수정 사항 |
| :---: | :--- | :--- | :--- | :--- |
| **E-1** | **데이터 부재 (Data Absence)** | 공공 API가 해당 조건/개인에게 제공되는 혜택이 아예 없음. | "현재 입력하신 정보로는 이용 가능한 복지 혜택을 찾기 어렵습니다. 다음 항목을 확인해 보세요:" 와 같이 **대안 질문** 제시. | `status_code: SUCCESS` (데이터는 있으나 내용물이 비어있음을 의미). <br> `risk_data.gap_score`: `0.0`. <br> `detail_info`: 빈 배열 `[]`와 함께, 안내 문구 포함 필드 추가 (`suggested_action`). |
| **E-2** | **네트워크 실패 (Network Failure)** | API 서버와의 통신 끊김 (Timeout 등). | "잠시 네트워크 연결 상태를 확인해 주세요. 데이터를 불러오는 데 문제가 발생했습니다." 와 같은 일반적인 안내 메시지 표시. | `status_code: FAILURE`. <br> **에러 코드**: `NETWORK_TIMEOUT`. <br> 상세 에러 메시지를 포함하여 재시도 횟수(Retry Count)와 함께 로그 기록. |
| **E-3** | **비정형/유효성 오류 (Malformed Input)** | 사용자가 API가 요구하는 형식과 다른 데이터(예: 문자열을 숫자 칸에 입력)를 전송함. | "제공해주신 [항목명]은 정확한 숫자로 입력해 주셔야 합니다." 와 같이 **입력 필드 단위**의 명확한 피드백 제공. | `status_code: FAILURE`. <br> **에러 코드**: `INPUT_VALIDATION_ERROR`. <br> 에러 발생 필드를 지정 (`error_field`: "소득_유형"). |
| **E-4** | **API 할당량 초과 (Rate Limit)** | 단기간 내 너무 많은 API 호출이 발생하여 서비스 제공처에서 접근을 제한함. | "현재 시스템 과부하로 데이터를 불러올 수 없습니다. 잠시 후 다시 시도해 주십시오." 와 같이 시간 기반의 안내 메시지 표시. | `status_code: FAILURE`. <br> **에러 코드**: `RATE_LIMIT_EXCEEDED`. <br> 다음 호출이 가능한 예상 시간을 명시 (`retry_after_seconds`). |
