### ✅ MiniFunnel E2E QA 최종 체크리스트 (Test Case Matrix)

| No. | 검증 영역 (Focus Area) | 테스트 케이스 설명 | 핵심 검증 기준 (Success Criteria) | 예상 실패 시나리오 (Failure Scenario) |
| :--: | :--- | :--- | :--- | :--- |
| **1** | ⚙️ **기술적 안정성** (Critical Path Stability) | 초기 유입(Landing)부터 Funnel 끝까지의 모든 버튼 클릭 및 화면 전환 과정. | *모든 단계에서 UI 깨짐 없이 매끄럽게 다음 상태로 전이되어야 함.* `ImportError` 같은 치명적인 스크립트 에러가 없어야 함. | 특정 장치/브라우저에서 컴포넌트가 겹치거나, 버튼 클릭 시 아무 반응이 없음 (Dead Click). |
| **2** | ⏳ **위기감 조성 타이밍** (Critical Timing Check) | 시스템 경고(CSA-UI) 발동 후, 필수 대기 시간(T+2,500ms) 이후 다음 단계로의 전환. | *시간 지연 로직이 정확히 작동하며*, 사용자가 느끼는 '시스템 오류' 감각을 유지해야 함. 타이밍이 너무 빠르거나 느리면 안 됨. | T+2,500ms가 의도치 않게 생략되거나(Skipped), 애니메이션 전환 시 버벅거림/렉 발생 (Jank). |
| **3** | 📈 **KPI 트래킹 유효성** (Data Logging Integrity) | Add-on 배치 지점 및 Exit Point에서의 사용자 액션 로깅. | *페이지뷰, 스크롤 깊이(Scroll Depth), 특정 CTA 클릭 여부*가 데이터베이스에 누락 없이 기록되어야 함. | 사용자가 Funnel을 이탈하는 순간(`Exit`)의 마지막 행동(예: 스크롤) 정보가 로그에서 사라짐. |
| **4** | ⚡️ **예외 처리 로직** (Failure/Edge Case Handling) | API 호출 실패, 네트워크 끊김 등 비정상적인 환경 시뮬레이션. | *시스템 경고 메시지(Deep Crimson Red)*를 통해 오류 원인과 다음 조치 방안을 명확히 안내하며 사용자 이탈을 방지해야 함. | 단순 "에러 발생" 메시지만 뜨고, 사용자가 무엇을 해야 할지 모르는 막다른 상태가 됨. |
| **5** | ✨ **브랜드 일관성 및 UX** (Aesthetic Consistency) | 모든 컴포넌트(헤더, 푸터, 알림창 등)에 Deep Crimson Red 테마 적용 여부 검토. | *모든 시각적 요소*가 통일된 톤앤매너를 유지하며, 공학적 권위(Technical Authority)를 느끼게 해야 함. | 특정 컴포넌트만 배경색이 바뀌거나, 색상이 너무 밝아져 전문성이 떨어지는 경우. |
