### 🚨 MiniFunnel 오류 페이지 시스템 (Error Page System) 디자인 브리프

**1. 기본 원칙 및 목적:**
*   **목적:** 사용자의 이탈(Abandonment)을 막고, 실패를 '시스템의 일시적 문제'로 정의하여 다시 복구 프로토콜(구매/문의)로 유도한다.
*   **톤 앤 매너:** 공학적 경고(Technical Alert), 신뢰성 기반 권위(Deep Navy 배경), 즉각적인 위기감(Crisis Red 강조).
*   **핵심 요소:** 오류가 발생한 지점을 '시스템 결함 코드'로 명시하고, 해결책을 제시하는 턴제 구조를 유지합니다.

**2. 상태별 UI/UX 및 인터랙션 스펙 (Component Specs)**

#### A. T1: 시스템 경고 단계 (System Alert - 입력 유효성 검사 실패)
*   **발생 시점:** 사용자가 필수 정보를 누락하거나 잘못된 형식으로 입력했을 때 (예: 휴대폰 번호, 이메일 포맷 오류).
*   **UI/UX 목표:** '실패'가 아닌 '재검증 필요' 메시지를 전달한다.
*   **디자인 구성 요소:**
    1.  **헤더 경고 바 (Critical Banner):** 페이지 상단에 가로 폭 전체를 차지하는 Deep Navy 배경의 얇은 배너가 깜빡이며 나타남.
        *   **텍스트:** `[SYSTEM ALERT] Protocol Deviation Detected: Input Integrity Check Required.`
        *   **디자인:** Crisis Red 네온 플래시 효과 적용. (CSS Class: `.alert-flash`)
    2.  **오류 필드 강조 (Field Error Focus):** 실패한 입력 필드 주변에 얇고 깜빡이는 빨간색 테두리(`1px solid #B00020`)를 적용합니다.
        *   **애니메이션:** `:focus-visible` 상태가 아니라, `onFailure` 이벤트 발생 시점에만 **반복적인 미세 깜빡임(Subtle Blink)**을 주어 주의를 집중시킵니다. (CSS Keyframe: `@keyframes blink { 0%, 100% { opacity: 1; } 50% { opacity: 0.6; } }`)
    3.  **오류 코드 제시:** 오류 필드 바로 아래에 해당 문제의 공학적 코드를 명시합니다. (예: `[DEFECT CODE: E-I401] - Invalid Format detected. Please verify the input protocol.` )

#### B. T3: 결제 실패 처리 단계 (Payment Failure - 카드/결제 게이트웨이 오류)
*   **발생 시점:** 결제 승인 과정에서 시스템적 문제나 카드사 문제로 거래가 실패했을 때. 가장 위기감이 높은 순간입니다.
*   **UI/UX 목표:** 사용자가 '돈을 잃었다'는 좌절감 대신, **'우리가 해결할 수 있는 기술적 장애물'**이라는 인식을 심어준다.
*   **디자인 구성 요소:**
    1.  **헤더 경고 바 (Critical Banner):** T1과 동일한 플래시 효과를 사용하되, 텍스트는 더욱 강력하게 변경합니다.
        *   **텍스트:** `[CRITICAL ERROR] Transaction Protocol Interrupted. System Check Required.`
        *   **애니메이션:** 깜빡임 외에, 전체 페이지 레이아웃이 미세하게 (1초 간격으로) 수직축 방향으로 떨리는 듯한 **'Glitch Effect'**를 주어 시스템의 오류 자체를 시각화합니다.
    2.  **오류 코드 및 원인 분석:** 실패 메시지를 추상적인 '결제 실패'가 아닌, 기술적 문제로 포장합니다.
        *   **헤드라인:** `[DEFECT ID: P-T304] - Payment Gateway Synchronization Error.` (공학 용어 사용)
        *   **본문:** "현재 외부 결제 프로토콜과의 동기화 오류가 감지되었습니다. 이는 사용자님의 신용도가 아닌, *시스템 간의 연결 불안정성* 문제입니다." (책임 회피 및 전문성 강조)
    3.  **복구 프로토콜 제시 (The Recovery Protocol):** 사용자가 이탈하는 것을 막고 다음 행동을 강제합니다.
        *   **옵션 1: 재시도 버튼 (Primary CTA):** 가장 크고 눈에 띄는 Crisis Red 버튼. (재시도는 '시스템이 복구된 후'라는 문구를 추가하여 심리적 장벽 낮추기)
        *   **옵션 2: 대체 프로토콜 요청 (Secondary CTA - 핵심 유도):** "자동 재시도가 실패할 경우, 전문가 상담(직접 연락)을 통해 수동으로 시스템 오류를 해결하세요."라는 문구와 함께 **전화번호 및 문의 링크**를 크게 배치합니다.
        *   **인터랙션:** 이 섹션에 도달하면 배경의 미세한 Glitch Effect가 멈추고, 대신 '안정적 연결'을 상징하는 Deep Navy의 부드러운 애니메이션으로 전환되어 심리적 안정감을 준 후 다음 행동(전화)으로 유도합니다.

**3. 기술 및 구현 스펙 요약 (Developer Handover)**
*   **컬러 팔레트:**
    *   Primary Background: `#0A192F` (Deep Navy - 권위, 신뢰)
    *   Accent/Alert: `#B00020` (Crisis Red - 경고, 위기)
    *   Text/Detail: `#CCD6F6` (Light Blue Gray - 전문 용어 강조)
*   **애니메이션 원칙:** 모든 실패 메시지는 *지속적인 불안정성(Flashing/Glitching)*을 보여주다가, 최종적으로 '해결책' 버튼 영역에서만 *안정화(Smooth Transition)*되는 흐름을 가져야 합니다.
