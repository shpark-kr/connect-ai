# 📋 작업 브리프

**원 명령:** [자율 사이클 — 2026-09-25] 1인 기업 24시간 운영 중. 회사 목표·각 에이전트의 개인 목표(_agents/{id}/goal.md)·최근 의사결정·메모리를 검토해서 지금 가장 가치 있는 단일 작업 1개를 결정하고, 적절한 1~2명 에이전트에게 분배해서 실행하세요. 같은 산출물을 반복하지 마세요 — 메모리에 비슷한 항목이 24시간 내에 있으면 다른 각도로 진전시키세요.

## 요약
시스템 안정성 확보 단계를 넘어 실제 콘텐츠 발행 파이프라인의 통합 테스트를 진행해야 합니다. 디자인된 모듈과 개발된 어댑터가 여러 플랫폼 환경에서 오류 없이 작동하는지 검증하여 최종 운영 준비도를 높이는 것이 목표입니다.

## 분배
- **💻 코다리**: Designer와 협업하여, 완성된 모듈형 컴포넌트 세트(노랑/흰색 고대비 자막, 위기 경고 타이머 등)를 활용한 End-to-End (E2E) 통합 테스트 스크립트를 작성하십시오. 특히 API 호출 실패(Rate Limit, Auth Error) 상황을 시뮬레이션하고, 시스템이 다운되지 않고 오류 코드를 반환하며 재시도하는 회복 탄력성 검증 루프를 핵심적으로 포함해야 합니다.
- **🎨 Designer**: 개발팀의 통합 테스트 요구에 맞춰, 모듈형 컴포넌트 세트를 시스템 레벨에서 관리할 수 있는 '최종 사용 가이드라인(Shorts_Module_Component_Guide.md)'을 업데이트하십시오. 이 가이드에는 모든 변수명, 클래스 이름, 애니메이션 타이밍 등 개발자가 코드를 직접 수정하지 않고도 전용 툴에서 제어 가능한 표준화된 컴포넌트 스펙이 상세히 포함되어야 합니다.
