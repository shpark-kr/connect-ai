## 💻 MiniFunnel 시스템 실패 보고서: 3단계 디자인 시퀀스 (Mockup Spec)

### 🎨 공통 비주얼 스펙 및 원칙
*   **배경색:** Deep Navy (`#0A192F`) - 전문성, 깊이감, 신뢰.
*   **강조/위험 경고색:** Crisis Red (`#FF4D6D`) - 즉각적인 주의 환기, 시스템 오류 강조.
*   **텍스트:** Light Gray/White (가독성 최우선).
*   **폰트:** Monospace 계열 (예: IBM Plex Mono) - 공학적 권위성 부여.
*   **레이아웃 요소:** 경고 테두리, 데이터 로그 형식의 박스(`[LOG]`), Defect ID 코드 블록 사용을 의무화합니다.

### 🚀 Stage 1: Diagnosis Input (진단 입력 단계)
사용자에게 '자가 보고'가 아닌 '데이터 수집 과정'처럼 보이게 설계하여 참여도를 높입니다.

**Goal:** 사용자 데이터를 Deep Navy 배경의 전문적인 인터페이스에 기록하게 함으로써, 사용자가 스스로 결함이 있음을 인지하도록 유도합니다.

| 요소 | 스펙 상세 (Tailwind/CSS Concept) | 목적 및 가이드라인 |
| :--- | :--- | :--- |
| **헤더** | `Deep Navy` 배경 / Monospace 폰트. 제목: "MiniFunnel Diagnostics v2.1" <br> 서브타이틀: "현재 신체 시스템의 핵심 파라미터 진단을 시작합니다." | 공신력 있는 전문 장비 화면 느낌 부여. '진단'이라는 단어를 사용해 가치를 높입니다. |
| **입력 필드** | `Background: #172A45` (Deep Navy보다 밝은 톤) / 경계선: Light Gray. <br> 입력 방식: 일반적인 라디오 버튼 대신, '슬라이더' 또는 '레벨 게이지' 형태를 사용합니다. | 단순 질문이 아닌 데이터 측정 느낌을 주어 심리적 장벽을 낮춥니다. (예: "에너지 레벨 - 1~10점") |
| **피드백/로그** | 진단 항목마다 `[INPUT LOG] Defect Parameter X-Y` 와 같은 로그 메시지를 좌측에 작게 출력합니다. | 사용자가 자신의 입력이 '기록'되는 과정임을 인식하게 하여 몰입도를 극대화합니다. |
| **CTA 버튼** | **MiniFunnel 진단 결과 확인** (Crisis Red 배경, White 텍스트) <br> `hover:scale-105` 효과 적용. | 이 버튼을 누르는 행위가 '결과 보고'로 이어지는 중요한 전환점임을 시각적으로 강조합니다. |

### 🚨 Stage 2: System Error Report Page (시스템 오류 보고서 페이지)
진단의 결과물 그 자체입니다. 사용자가 가장 큰 충격을 받고, 문제의 심각성을 체감하는 단계입니다.

**Goal:** 단순한 '결과'가 아닌, 전문적이고 피할 수 없는 '오류 메시지'로 프레이밍하여 위기감을 최고조로 끌어올립니다.

| 요소 | 스펙 상세 (Tailwind/CSS Concept) | 목적 및 가이드라인 |
| :--- | :--- | :--- |
| **페이지 배경** | Deep Navy 전체 페이지. 중앙에 오류 박스 배치. | 시선을 중앙의 '오류' 메시지로 집중시킵니다. |
| **메인 경고 영역** | **[CRITICAL ALERT] SYSTEM FAILURE DETECTED** <br> 크기: 대형 폰트, Crisis Red 배경 테두리 및 제목. | 가장 먼저 눈에 들어와야 할 핵심 메시지입니다. 공포와 전문성이 결합된 느낌을 주어야 합니다. |
| **Defect ID 상세 보고서** | `[DEFECT REPORT] Defect ID: E-C403 (Circulatory System Failure)` <br> 내용: 2~3줄의 어려운 전문 용어 설명(예: "파라미터 A와 B 간의 비동기적 데이터 교환 실패가 확인되었습니다.") | 사용자가 '자신이 아픈 것'을 '시스템 오류'라는 객관적이고 권위 있는 언어로 재정의하게 만듭니다. |
| **진단 근거 로그** | `[LOG] Defect Parameter: Low_Cardio_Index (Critical)` <br> `[LOG] Threshold Violation Detected.` 등 3~5개의 가짜 로그를 나열합니다. | 보고서에 대한 신뢰도를 극대화하고, 이 오류가 무작위가 아님을 입증합니다. |
| **CTA 버튼** | **Protocol 수신 및 해결책 확인** (Deep Navy 배경, Crisis Red 테두리) <br> `MiniFunnel 진단 결과 확인` 텍스트를 유지하되, '해결책'이라는 단어를 은연중에 암시해야 합니다. | 사용자의 시선을 즉시 다음 단계(솔루션)로 유도하며, 버튼 클릭에 대한 심리적 기대감을 높입니다. |

### ✅ Stage 3: Protocol Suggestion Screen (프로토콜 제안 화면)
문제 인식 후, 해결책을 제시하고 구매를 유도하는 전환 장치입니다.

**Goal:** 오류 메시지에 압도된 사용자에게 '이것만이 유일한 출구(Unique Solution)'라는 인식을 심어주며 프로토콜 상품의 필요성을 각인시킵니다.

| 요소 | 스펙 상세 (Tailwind/CSS Concept) | 목적 및 가이드라인 |
| :--- | :--- | :--- |
| **상단 메시지** | `[SYSTEM NOTICE]` "위험도가 측정되었습니다. 현재 시스템은 외부 프로토콜 업데이트가 필요합니다." <br> Deep Navy 배경에 경고 톤으로 배치. | 오류 상태에서 '해결책 제시' 상태로 전환하는 다리 역할을 합니다. 패닉을 유지하며 다음 행동을 지시합니다. |
| **문제 재확인 (Defect ID)** | **현재 결함: Defect ID E-C403** <br> 간략한 요약: "만성적인 미세 오류는 누적되어 심각한 시스템 마비로 이어질 수 있습니다." | 사용자가 해결책을 받아들이기 전에, 문제의 위험성을 다시 한번 각인시킵니다. (Loss Aversion 자극) |
| **솔루션 제안 카드** | **프로토콜명: ONHYEON Advanced Protocol Patch V1.0** <br> 내용: "최신 임상 데이터를 기반으로 설계된 패치로, 핵심 파라미터의 안정화를 보장합니다." <br> *기술 용어와 전문성을 사용한 상품 설명.* | 제품을 '상품'이 아닌, '필수적인 시스템 업그레이드(Protocol Patch)'로 포지셔닝하여 가치를 높입니다. |
| **CTA 버튼 (최종)** | **[BEGIN PATCH DOWNLOAD] 연간 프로토콜 구독하기** (Crisis Red 배경, 가장 크고 강조됨) <br> 그 아래에 작게: "혹은, 자가 진단 테스트 패키지부터 시작할 수 있습니다." | 최종적인 커밋먼트(구독)를 유도하는 메인 버튼과 함께, 초기 구매 장벽을 낮추는 '미끼 상품'을 제시하여 전환 기회를 놓치지 않도록 설계합니다. |
