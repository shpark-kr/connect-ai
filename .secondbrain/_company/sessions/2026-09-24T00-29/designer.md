## 📌 1. 개요 및 목표
*   **위젯 이름:** 온현 전문가 재정 진단 시스템 (OnHyun Financial Diagnostic System)
*   **목표:** 사용자가 자신의 현재 재정 상황(Pain Point)을 입력하면, 공적 데이터를 기반으로 'Gap' 규모를 수치화하고, 이 Gap을 메우기 위한 구체적인 솔루션과 CTA 다운로드 페이지로 유도하는 Funnel 기능을 구현한다.
*   **톤앤매너:** 전문적 경고 (Authority Warning). 신뢰감을 주는 다크 네이비/골드 조합 유지.
*   **원칙:** Mobile-First 설계(최소 터치 영역 48px 준수) 및 모든 상태(Success, Error, Loading)에 대한 명확한 시각화가 필수이다.

## 💡 2. UI/UX 시퀀스 다이어그램 (Interactive Flow Map)
위젯은 총 5단계의 순차적 흐름을 갖는다. 각 단계는 사용자의 심리적 몰입도와 신뢰도를 유지하도록 설계되어야 한다.

| Step | 사용자 액션 (User Action) | 시스템 피드백 (System Feedback) | 기술 구현 요소 (Tech Requirement) | 비고 (Notes) |
| :--- | :--- | :--- | :--- | :--- |
| **1. 진입/초기 상태** | 위젯 접근 (페이지 로딩 시 자동 노출) | 간결한 제목 + 공포 유발 질문 제시. 입력 필드 활성화 대기. | `Initial State` 컴포넌트. 최소 48px 크기의 '진단 시작' 버튼 필수. | **[CTA]** 진입 즉시 위협감(FOMO)을 주어 입력 유도. |
| **2. 데이터 입력/처리** | 핵심 정보 (예: 예상 은퇴 나이, 현재 연금액 등) 입력 및 제출 버튼 클릭. | 1. 로딩 스켈레톤 UI 표시 (Loading State). 2. 시스템 메시지 ("정확한 진단을 위해 데이터를 분석하는 중입니다...") 노출. | `API Call` 트리거. 지수 백오프(Exponential Backoff) 재시도 로직 필수 적용. | 데이터 처리 과정에서 사용자가 이탈하지 않도록 **전문적이고 신뢰감 있는 애니메이션**이 중요. |
| **3. 진단 결과 표시 (Success)** | 시스템 분석 완료. 핵심 Gap 수치와 시나리오 그래프 제시. | ① '재정 위험 지수'를 가장 크게 노랑(Amber) 경고색으로 표시. ② 현재 상태 vs 개선 목표의 'Gap 크기'를 비교하는 차트/그래프 배치. ③ 명확한 솔루션 3가지 목록 제시. | `Result Display` 컴포넌트. 결과값에 대한 시각적 강조 (Reveal 효과). | **[가장 중요]** 수치화된 Gap 데이터가 Funnel의 핵심 유도 장치가 된다. |
| **4. 상세 설명 및 신뢰 구축** | 결과 그래프 아래, 공적인 근거와 전문가 코멘트를 배치. | "이러한 위험은 법적/제도적 사각지대에서 기인할 수 있습니다." 등 전문적 경고 텍스트 제시. | `Authority Box` 컴포넌트 (출처: 정부기관 로고 및 링크 삽입). | 단순히 정보를 주는 것이 아니라, **문제의 원인을 재정적으로 '진단'** 해주는 느낌을 주어야 한다. |
| **5. 최종 CTA/전환 유도** | "전문가 상담 가이드 다운로드" 또는 "1:1 진단 신청하기" 버튼 클릭. | 팝업창 혹은 별도의 섹션으로 전환 유도. (Funnel 최적화) | `CTA Button` 컴포넌트. **터치 영역 최소 60px 확보** 권장. 다운로드/전환 API 연동 필수. | 가장 강력한 경고 메시지: "지금 조치를 취하지 않으면, \[예상되는 재정 손실 금액]이 발생할 수 있습니다."를 배치한다. |

## 🚨 3. 예외 케이스 및 오류 처리 디자인 명세 (Error/Edge Case Handling)
시스템의 신뢰도를 유지하기 위해 모든 실패 상황을 사용자 친화적이고 전문적으로 처리해야 한다.

### 3-1. 로딩 상태 (Loading State Design)
*   **디자인:** 단순 스피너(Spinner) 금지. 데이터 분석 과정을 암시하는 **'데이터 플로우 시퀀스' 형태의 애니메이션** 사용 권장.
*   **메시지:** "\[기관명]의 공적 데이터를 기반으로 3단계 Gap 분석을 진행 중입니다. 잠시만 기다려 주십시오." (기술적인 용어를 사용하여 신뢰도 확보)
*   **UX 요소:** 스켈레톤 UI를 적용하여, 결과가 나올 빈 공간과 구조를 미리 보여주어 로딩 시간을 체감적으로 줄인다.

### 3-2. API 호출 실패 (Failure State: Network/Server Error)
*   **시각화:** 빨간색(Red - Danger) 경고색을 사용하여 명확한 경고 상태임을 알린다.
*   **메시지 구성:**
    1.  **경고 제목:** "진단 시스템 오류 발생" (가볍게 느껴지지 않도록 전문적인 톤 유지).
    2.  **설명:** "현재 외부 데이터 API와의 연결에 일시적인 문제가 발생했습니다. 잠시 후 다시 시도하거나, 수동으로 정보를 입력해 주십시오." (사용자에게 할 일을 제시)
    3.  **액션 버튼:** [재시도] (Retry - 자동화된 재시도 로직을 설명), [문의하기]

### 3-3. 데이터 부재/유효성 오류 (Failure State: Data Validation Error)
*   **발생 조건:** 사용자가 필수 입력 필드를 비워두거나, 논리적으로 모순되는 데이터를 입력했을 경우.
*   **시각화:** 해당 필드 주변에 경고색(Amber Yellow)의 얇은 테두리를 표시하고, 아이콘 (⚠️)을 배치한다.
*   **메시지 구성:** "이 항목은 재정 진단에 필수적입니다. **'현재 연금 수령액'**을 정확히 입력해 주셔야 Gap 분석이 가능합니다."
*   **UX 고려사항:** 오류 메시지는 필드 바로 아래, 사용자가 *즉각적으로 무엇을 고쳐야 하는지* 명확하게 알려주어야 한다.

## 📐 4. 모바일 최적화 및 컴포넌트 사양 (Mobile-First & Component Specs)
모든 요소는 세로 방향(Portrait) 스크롤에 최적화되어야 하며, 터치 인터페이스를 우선한다.

| 컴포넌트 | 필수 크기/규격 | 기술 구현 요구사항 | 참고 사항 |
| :--- | :--- | :--- | :--- |
| **전체 위젯 컨테이너** | 최소 폭 320px 이상 확보 (Viewport Width) | 반응형 디자인(Responsive Web Design) 적용. 섹션 간의 여백(Padding/Margin)은 모바일 기준 24px 유지. | 화면이 작아도 콘텐츠가 답답하지 않도록 적절한 공백 처리가 핵심. |
| **입력 필드 (Input)** | 최소 높이 56px, 터치 영역 최소 48px 확보. | `input type="text"`, `select` 태그 사용 시, 기본 OS의 네이티브 UI를 활용하되 커스텀 테두리(다크/골드) 적용. | 키보드 표시 시 레이아웃이 깨지지 않도록 고정된 섹션 구조가 필요함. |
| **CTA 버튼** | 가로 폭 100%, 최소 높이 60px 확보 (최상위 CTA). | `onClick` 이벤트에 Funnel API 호출 연동 필수. 마우스 오버/터치 시 색상이 변하는 애니메이션(Hover Effect) 구현. | 가장 눈에 띄는 경고색 배경을 사용하고, 문구는 **명령형**으로 작성해야 함 ("지금 확인하기", "진단 받기"). |
| **경고 박스 (Warning Box)** | 가로 폭 100%. 높이는 내용물에 따라 유연하게 조정. | `role="alert"` 접근성 속성을 적용하여 스크린 리더가 경고임을 인식하도록 한다. 배경색은 #FFB800 계열 사용. | 공적 제도 근거를 제시할 때 활용하며, 신뢰도를 높이는 핵심 장치이다. |
