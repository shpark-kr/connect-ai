**[작성 목적]**
본 문서는 온현의 Funnel 핵심 전환 요소인 '전문가 진단(Expert Diagnosis)' 섹션에 사용될 모든 인터랙티브 웹 컴포넌트의 디자인 의도, 기술적 사양, 사용자 흐름을 개발팀(코다리)에게 명확히 전달하여, 모바일 환경에서의 구현 오류를 최소화하고 일관된 브랜드 경험을 보장하는 것을 목표로 합니다.

**[🎨 Design System 원칙]**
1.  **모바일 우선 (Mobile-First):** 모든 컴포넌트는 스마트폰 세로 화면(최소 너비 375px 기준)에 최적화되어야 합니다.
2.  **접근성:** 색상 대비는 WCAG AA 레벨을 준수해야 하며, 모든 터치 영역은 최소 **48px x 48px** 이상의 충분한 공간을 확보합니다.
3.  **톤앤매너:** '전문적 경고(Professional Alert)'의 느낌을 유지하기 위해 Dark Navy(#1A237E)와 Critical Red(#D32F2F), 강조용 Gold(#FFC107)를 제한적으로 사용합니다.

## Ⅰ. 컴포넌트별 상세 사양 및 인터랙션 정의

### 1. Gap 리스크 위젯 (Gap Risk Widget - 핵심 진단 요소)
*   **역할:** 사용자 입력 데이터와 표준 기준 간의 격차(Gap)를 시각적으로 가장 먼저 경고하는 역할.
*   **시각적 사양:**
    *   배경: Dark Navy 배경에 Critical Red 포인트 사용.
    *   구조: [위험 레벨 아이콘] + [핵심 메시지 (H2, 폰트 크기 18px)] + [Gap 수치 (크게 표시)].
    *   **[필수 인터랙션]**: 위젯이 로딩되거나 데이터가 계산되어 나타날 때, 경고 레벨 아이콘과 Gap 수치가 **부드럽게(Smooth)** 페이드 인(Fade In) 되어야 합니다. (Duration: 300ms).
*   **기술적 제약:**
    *   데이터 변화 시: 기존 숫자가 사라지기 전, 짧은 애니메이션 효과(예: 스케일 다운 후 재진입)를 적용하여 데이터가 **갱신되고 있음**을 사용자에게 인지시켜야 합니다. (Duration: 200ms).

### 2. Primary CTA 버튼 라이브러리 (Primary Call-to-Action Button)
*   **역할:** 사용자가 다음 단계로 이동하도록 유도하는 가장 중요한 클릭 지점.
*   **시각적 사양:** 배경색은 대비가 높은 Gold(#FFC107) 또는 Dark Navy에 Critical Red 텍스트 조합을 주력으로 합니다. (2가지 버전 제공).
    *   폰트: 고대비, 명확한 산세리프 계열 사용.
    *   크기: 모바일 환경에서 너비 **90%**를 차지하도록 설정하며, 최소 높이는 56px를 유지합니다.
*   **[필수 인터랙션]**:
    *   **Hover/Focus State:** 버튼을 누르거나 포커스 될 때, 배경색이 순간적으로 어두워지며(Darken Effect) 미묘한 그림자(Soft Shadow)가 생기는 효과를 적용합니다. (Transition: 150ms).
    *   **Click Feedback:** 클릭 시 즉각적인 버튼 크기 축소(Scale Down) 피드백을 제공하여, 사용자가 성공적으로 입력했다는 물리적 감각을 주어야 합니다.

### 3. 후속 리포트 목업/미리보기 (Report Preview Widget)
*   **역할:** CTA를 클릭하기 전에 '무엇을 얻게 되는지' 기대감을 심어주는 시각 자료.
*   **시각적 사양:** 실제 보고서의 일부 섹션(예: 그래프 3개, 핵심 요약 박스 2개)을 Mockup 형태로 보여줍니다.
    *   배경톤: 전문성을 강조하는 은은한 그레이 계열 사용.
    *   요소: 데이터 시각화는 단순 차트가 아닌, **"온현만의 독점 분석 결과"**라는 느낌의 심볼과 함께 배치해야 합니다.
*   **[필수 인터랙션]**: 이 위젯 자체는 클릭 가능한 요소라기보다는 배경 설명이므로 애니메이션은 최소화합니다. 다만, 스크롤 시 부드럽게 나타나는 **Fade In (400ms)** 효과를 적용하여 정보가 점진적으로 공개되는 느낌을 주어야 합니다.

## Ⅱ. 인터랙티브 위젯 작동 시퀀스 다이어그램 (State Machine Flow)

**[사용자 흐름]**: 사용자 진입 $\rightarrow$ 데이터 입력/계산 $\rightarrow$ 경고 인지 $\rightarrow$ 액션 유도 $\rightarrow$ Funnel 전환

| Step | 주체 | 동작 (Action) | 시스템 응답 및 사양 (Requirement) | 기술적 제약 (Constraint) |
| :--- | :--- | :--- | :--- | :--- |
| **1. 진입** | User | 페이지 로딩 | Gap 리스크 위젯, CTA가 동시에 나타남. | 모든 컴포넌트는 뷰포트(Viewport)에 진입할 때 Fade In (300ms). |
| **2. 데이터 계산** | System/Client | 사용자 입력값 기반 Gap 수치 계산 및 API 호출 전처리. | `Gap 리스크 위젯`이 초기 경고 수치를 표시하며, 애니메이션으로 주목도를 높임. | 로딩 상태는 빈 공간에 '진단 중...' 텍스트를 보여주며 좌우로 은은하게 깜빡여야 함. (Loop: 1s 간격). |
| **3. 경고 인지** | System/Client | Gap 수치가 임계점(Threshold)을 초과하여 Critical Red 레벨로 확정됨. | `Gap 리스크 위젯`의 색상과 크기가 즉시 변화하며, 시각적 충격을 극대화함. | **경고 발생 순간:** 경고 아이콘 주변에 짧은 펄스 효과 (Pulse Effect)를 적용합니다. (Duration: 500ms). |
| **4. 액션 유도** | System/Client | Funnel 전환을 위해 `Primary CTA`가 활성화됨. | CTA 버튼이 가장 눈에 잘 띄는 위치에 배치되며, 사용자의 시선을 따라 이동하는 듯한(Micro-Animation) 효과를 적용합니다. | CTA의 **Active State** (클릭 직전 상태)를 명확하게 구분하여 개발자가 쉽게 구현할 수 있도록 별도 CSS 클래스를 정의해야 합니다. |
| **5. 전환 및 API 호출** | User $\rightarrow$ System | 사용자가 CTA 버튼을 클릭함. | 1. CTA가 눌리는 피드백(Scale Down). 2. 로딩 스피너가 표시됨 (진행 바 형태 권장). 3. 백엔드에 데이터 전송 시작. | **API 호출 과정:** 로딩 화면에서 "데이터 분석 중... 잠시만 기다려 주세요." 메시지를 반드시 보여주며, 추측 가능한 대기 시간을 제공해야 함. |
| **6. 결과 확인** | System/Client | API 응답을 받아 '후속 리포트 목업'으로 이동하거나 다운로드 페이지로 리다이렉션됨. | 최종 성공 또는 실패 상태 메시지 표시 및 Funnel의 다음 단계(Next Step)를 명확히 제시함. | **성공:** 긍정적인 색상 (Deep Blue/Green 계열)을 사용하고, "진단 완료!"와 같은 구체적 문구를 통해 안도감을 제공해야 함.
