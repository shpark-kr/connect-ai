### 🛠️ Funnel 최종 시각 검증 체크리스트 (QA Protocol)

이 체크리스트는 개발자가 코딩한 로직이 다음의 비주얼 원칙과 일치하는지 확인하기 위한 표준화된 질문 세트입니다.

#### 1. 핵심 컴포넌트: `[Module_StatusIndicator]`
| 검증 항목 | 시나리오/상태 | 목표 디자인 사양 (Design Spec) | QA Pass 기준 (Pass Criteria) |
| :--- | :--- | :--- | :--- |
| **Error Level 1** (Critical) | HOMA-IR 임계치 초과 등 치명적 실패. | 배경: Deep Crimson Red (`#8B0000`). 아이콘: 경고삼각 + 느낌표. 애니메이션: 깜빡임(Flashing) 효과 필수. 시각 계층 구조: 가장 크고, 화면 중앙 상단에 고정. | 1. 색상 코드 및 깊이(Saturation)가 정확한지 확인. <br> 2. CSS 애니메이션 `@keyframes` 타이밍과 반복 주기가 설정된 대로 작동하는지 확인. |
| **Error Level 2** (Warning) | 생활 습관 개선 필요 단계 진입. | 배경: Orange/Amber (`#FF8C00`). 아이콘: 느낌표만 사용. 애니메이션: 부드러운 색상 변화(Soft Pulse). 시각 계층 구조: Critical 아래에 위치하며, 가시성이 높아야 함. | 1. Red에서 Amber로의 전환이 너무 급격하지 않고 `easing` 함수를 거치는지 확인. <br> 2. 경고 문구(`Warning:`)가 명확하게 구분되는지 확인. |
| **Recovery State** (Success) | 개선 솔루션 도입/진단 완료 성공. | 배경: Soft Gold (`#FFD700`). 아이콘: 체크 마크(✓). 애니메이션: 점진적 밝아짐(Fade-in Glow). 시각 계층 구조: 긍정적, 안정감을 주되 Red의 위기감을 완전히 상쇄하지 않아야 함. | 1. 금색 사용이 '승리감'보다 '전문적 해결책 제시' 느낌을 주는 톤앤매너인지 확인. <br> 2. 복잡한 애니메이션 없이 부드럽고 신뢰성 있는 전환(Smooth Transition)만 제공하는지 확인. |

#### 2. 트랜지션 로직 (The UX Flow)
| 검증 항목 | 세부 액션 및 타이밍 | 기술적 요구 사항 (Technical Requirement) | QA Pass 기준 |
| :--- | :--- | :--- | :--- |
| **Red $\to$ Gold 전환** | 오류 진단 실패(Red) $\to$ 해결책 제시/데이터 입력(Gold). | 1. Red 상태가 일정 시간($T_{red}$) 유지된 후, 사용자 액션 유도에 따라 부드럽게 색상이 변화해야 함. <br> 2. **지정 이징 커브:** `cubic-bezier(0.4, 0, 0.2, 1)` (부드러운 가속). | Red의 강한 위기감에서 Gold의 안정감으로 넘어갈 때, 시각적 '안도감'을 주는 전환 효과가 명확해야 함. 갑작스러운 색 변화는 실패로 간주함. |
| **Hierarchy 유지** | 다단계 에러 메시지 출력 (예: Level 1 $\to$ Level 2). | 상위 레벨의 오류(Level 1) 컴포넌트가 하위 레벨의 오류(Level 2)를 시각적으로 압도해야 함. (Size, Z-index, Contrast 대비 사용). | 같은 화면에 여러 에러 메시지가 있을 경우, 가장 심각한 오류만 **최우선 포커스 영역**을 가져야 하며, 이 영역이 다른 요소를 가릴 정도의 강도를 가져야 합니다. |

### 📝 개발자 브리프: Funnel UI/UX 수정 요청 사항 (Developer Brief)

코다리 에이전트가 테스트를 진행하는 동안 발견될 수 있는 *잠재적* 시각적 비일관성을 최소화하기 위해, 다음 두 가지 사양을 개발자에게 사전 반영하도록 지시합니다.

**1. Deep Crimson Red의 명도(Luminosity) 조정:**
*   **문제점 예측:** 기술 구현 과정에서 Pure CSS/JS를 사용하면 색상이 너무 강하거나 채도가 과하게 높아져 실제 '경고'보다는 '디스플레이 오류'처럼 보일 수 있음.
*   **수정 지시:** Deep Crimson Red는 `#8B0000`을 유지하되, *배경색으로 사용할 경우* `opacity: 0.15` 정도의 투명도를 적용하여 내용물(텍스트/그래프)에 집중할 수 있는 '깊이감'과 '압박감'만 전달하도록 조정합니다. (절대 순수 원색 배경 사용 금지).

**2. 에러 코드 레벨별 폰트 스타일 분리:**
*   **문제점 예측:** 모든 오류 메시지에 동일한 본문 폰트를 사용할 경우, 어떤 정보가 가장 중요한지 파악하기 어려움.
*   **수정 지시:**
    *   **[Error Code (예: HOMA-IR > 3.5)]**: `monospace` 계열의 폰트(Monospace Font)를 사용하고, **Bold체**로 강조하여 전문성과 '데이터 오류'라는 느낌을 부여합니다. 이 코드가 메시지의 시각적 위계를 담당하게 합니다.
    *   **[설명 문구]**: 일반적인 본문용 산세리프 폰트를 유지하되, Error Code가 주는 공학적 권위감을 보완하는 역할을 수행하도록 합니다.
