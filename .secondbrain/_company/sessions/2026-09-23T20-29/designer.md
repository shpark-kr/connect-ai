## 📑 개요 및 목표
**명칭:** \[온현] 공적 지원 Gap 리스크 측정기 (Expert Diagnostic Scorecard)
**목표:** 사용자에게 '현재 상태(Before)'의 재정적 위험성을 **숫자화된 충격(FOMO)**으로 인지시키고, 전문 상담/서비스 이용을 통해 얻는 '미래의 이득(After)'이라는 해결책에 집중시켜 Funnel 전환율 극대화.
**사용 환경:** 모바일 최우선 (Mobile-First). 반응형 웹 컴포넌트.

## 📐 브랜드 및 시각적 제약 조건 (Brand & Visual Constraints)

### 1. 컬러 팔레트 정의
| 요소 | 색상 코드 | 용도/의미 | 비고 |
| :--- | :--- | :--- | :--- |
| **메인 배경** | `#1A202C` (Dark Navy) | 전문성, 신뢰, 안정감. 섹션 전체 배경색. | 어두운 테마 유지 필수 |
| **강조/위험 경고** | `#D9534F` (Crimson Red) | 'Before' 상태의 위험성 강조, 긴급 상황 알림. | 핵심 Gap 수치에 사용 |
| **해결책/긍정 전환** | `#FFC107` (Golden Yellow) | 'After' 솔루션 제시, 기회비용 확보 가능성을 시각화. | CTA 버튼 및 해결책 그래프에 사용 |
| **텍스트 기본색** | `#E2E8F0` (Light Gray) | 본문 텍스트, 가독성 최우선. | 높은 명도 대비 유지 |

### 2. 타이포그래피 (Typography)
*   **폰트:** Noto Sans KR 또는 Pretendard (웹 환경에서 가장 가독성이 높고 전문적인 느낌을 주는 산세리프 계열).
*   **크기 원칙:** 제목(H1/H2)은 32px 이상, 본문 핵심 수치는 24px 이상으로 **대형화하여 시선 강탈**.

### 3. 레이아웃 및 모바일 가독성 (Layout & Mobile Constraints)
*   **최상위 제약:** 모든 요소는 화면 폭(Viewport Width)의 90%를 넘지 않도록 중앙 정렬합니다.
*   **터치 영역 최소 크기 (Touch Target):** 버튼, 슬라이더, 클릭 가능한 카드 등 **모든 인터랙티브 요소는 최소 가로/세로 48px 이상**을 확보해야 합니다. (iOS Human Interface Guideline 준수)

## 🖥️ 컴포넌트별 상세 사양 및 애니메이션 로직 (Component Specs & Logic Flow)

### 1. [섹션 A] 진단 점수 요약 카드 (The Scorecard - 최상단 배치)
*   **구성:** 현재 리스크 레벨(Level), 종합 스코어(Score/100점 만점), 위험 경고 메시지.
*   **데이터 인터페이스:** `[API_CALL: get_risk_score]` 호출 결과에 따라 텍스트와 색상이 동적으로 변경되어야 합니다. (예: 점수 60점 미만 $\rightarrow$ Crimson Red 배경 + '위험' 배지)
*   **애니메이션 로직:** 페이지 로드 시, 스코어 숫자는 **카운트업 애니메이션(Count-up Animation)**을 통해 부드럽게 등장해야 합니다. (T+0s 시작 $\rightarrow$ 1초 동안 서서히 증가).

### 2. [섹션 B] Gap 비교 그래프 (The Comparison Graph - 핵심 콘텐츠)
*   **형태:** 시계열 차트(Line Chart)와 누적 막대 그래프(Stacked Bar Chart)의 하이브리드 형태를 사용합니다.
*   **데이터 처리:** 최소 3가지 데이터 라인 필요: `[기준_현행]` (점선/회색), `[Gap_추정치]` (Crimson Red, 추락하는 화살표 모양 강조), `[Solution_최적화]` (Golden Yellow, 상승 그래프).
*   **애니메이션 로직:** 스크롤 기반 애니메이션(Scroll-Triggered Animation)을 적용합니다. 사용자가 섹션 B에 도달하면, **그래프의 데이터 라인이 0부터 해당 수치까지 부드럽게 그려지면서(SVG Path Drawing)** 나타나야 합니다. (총 소요 시간: 1초~1.2초).
*   **인터랙션:** 그래프 위에 마우스 오버/모바일 터치가 발생하면, 해당 시점의 **'Gap 금액 차이'**를 툴팁(Tooltip) 형태로 명확히 표시해야 합니다.

### 3. [섹션 C] 위험 진단 체크리스트 (The Diagnostic Checklist - 전환 유도 섹션)
*   **목표:** 사용자 참여를 통한 인지적 개입 유도.
*   **구성:** 공통 질문 리스트(예: "연금 수령액을 재점검하셨습니까?"), 각 질문당 'Yes/No' 버튼 제공.
*   **인터랙션 로직 (가장 중요):**
    1.  사용자가 'No'를 선택할 때마다, **Crimson Red의 경고 아이콘과 함께 "손실 가능성 측정"이라는 피드백을 즉각적으로 줍니다.**
    2.  체크리스트 하단에 누적된 '위험 점수'가 실시간으로 계산되어야 하며, 이 점수는 최종 CTA 버튼 근처에 배치됩니다.
*   **CTA 전환:** 체크리스트 완료 후 (또는 특정 위험 점수 임계치 초과 시), **Golden Yellow 색상의 메인 CTA 버튼이 활성화(Active)되고 애니메이션 효과가 발생해야 합니다.**

## ⚙️ 개발자 필수 구현 가이드라인 (Codari Developer Checklist)

1.  **API 연동 우선순위:** `get_risk_score` $\rightarrow$ `calculate_gap_data` $\rightarrow$ `log_user_interaction` 순서로 호출 안정성을 확보해야 합니다. 모든 API 호출은 **지수 백오프(Exponential Backoff)** 기반의 재시도 로직을 필수적으로 적용합니다.
2.  **접근성 (Accessibility):** 색맹/색약 사용자를 위해 경고 메시지는 반드시 **텍스트 설명과 아이콘 조합**으로 2차 전달되어야 합니다. (Color Blind Safe Design)
3.  **퍼포먼스:** 모든 애니메이션은 하드웨어 가속(Hardware Acceleration)을 활용하여 부드럽게 구현해야 하며, 페이지 로딩 속도에 영향을 주지 않도록 최적화해야 합니다.
