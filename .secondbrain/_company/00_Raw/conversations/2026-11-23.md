## 🔬 [Case Study 1] 인슐린 저항성 (Insulin Resistance)
**측정 지표:** 당화혈색소(HbA1c) / 공복 혈당(Fasting Glucose)

| 구분 | 정상 범위 (Normal State) | 경계 위험 범위 (Pre-Defect ID) | 심각한 Defect ID 상태 (Critical Failure) | 기능적 오류 시나리오 (Functional Error Narrative) | 관련 의학/생물학 용어 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **HbA1c (%)** | 4.5% 이하 | 5.7% ~ 6.4% | **6.5% 이상 (Defect ID)** | *에너지원 선택 실패:* 인슐린 신호가 세포 수용체에 도달하지 못하고 방황함. 근육/지방세포는 혈액 속 포도당을 에너지로 인식하지 못하며, 췌장은 과부하되어 고혈당 상태를 유발하는 악순환이 발생함. | 인슐린 신호 전달 체계 교란 (Insulin Signaling Dysfunction), 세포 에너지원 비효율성(Cellular Energy Inefficiency), 만성 대사 이상 (Chronic Metabolic Dysregulation) |
| **공복 혈당 (mg/dL)** | 80 이하 | 90 ~ 125 | **140 이상 (Defect ID)** | *혈류 역학적 실패:* 간과 근육이 포도당을 제때 흡수하지 못하고, 과잉의 혈당이 혈관 내벽에 지속적으로 손상을 입히기 시작함. 이는 미세 혈관 합병증(Microvascular Complications)의 시발점이 됨. | 전신성 염증성 고혈당 (Systemic Inflammatory Hyperglycemia), 말초 신경병증 위험 증가 (Risk of Peripheral Neuropathy), 심혈관계 부담 가중 (Increased Cardiovascular Burden) |

**목표:** 사용자의 주요 건강 지표(예: HbA1c, 혈압 등)의 현재 수치와 정상 범위 간의 **'시스템적 결함 Gap'**을 시각화하여 불안감을 최고조로 끌어올리고 전문 진단 서비스로의 이탈을 유도한다.

**기술 스택 가정:** ReactJS + Styled Components (CSS Variables 활용)
**브랜드 톤앤매너:** 긴급, 과학적, 권위적 (Crisis/Scientific Authority)
**핵심 색상 팔레트:**
*   `--color-normal`: #1A3750 (다크 네이비 - 안정적인 배경색)
*   `--color-warning`: #FFC107 (앰버/골드 계열 - 주의, 위험 신호)
*   `--color-critical`: #D32F2F (진홍색/레드 - 시스템 오류, 긴급 경보)
*   `--color-text-primary`: #E0E0E0

### 1. Props 정의 (Developer Input Interface)

개발자가 반드시 주입해야 할 데이터와 변수 목록입니다.

| Prop Name | Type | Description | Example Value | 필수 여부 |
| :--- | :--- | :--- | :--- | :--- |
| `metricName` | string | 측정 항목의 이름 (예: HbA1c, 혈압) | "당화혈색소(HbA1c)" | O |
| `currentValue` | number | 사용자가 측정한 현재 수치 | 6.8 | O |
| `normalMin` | number | 정상 범위 최소값 | 4.0 | O |
| `normalMax` | number | 정상 범위 최대값 | 6.0 | O |
| `criticalThreshold` | number | 임계 실패 기준점 (Critical Failure) | 7.5 | O |
| `unit` | string | 단위 표시 (예: %, mmol/L) | "%" | O |

### 2. 컴포넌트 구조 및 레이아웃 (Visual Hierarchy)

컴포넌트는 크게 세 부분으로 나뉩니다. 전체적으로 다크 네이비 배경 위에 밝은 골드 계열의 데이터가 대비되도록 설계합니다.

1.  **Header Zone:** 측정 항목명 (`metricName`)과 현재 수치(`currentValue`)를 가장 크고 강렬하게 배치.
2.  **Visualizer Core (그래프 영역):** 핵심 결함 Gap을 보여주는 시각적 캔버스. 애니메이션이 발생하는 주 무대입니다.
3.  **Status Footer Zone:** 현재 상태(정상/경고/위험)와 즉각적인 행동 유도 문구(CTA 연결 전 단계)를 배치합니다.

### 3. 핵심 로직: State 기반 인터랙션 명세 (React State Logic Flow)

컴포넌트는 `currentValue`가 변하는 순간, **State Transition**을 거치며 애니메이션이 실행되어야 합니다. 이 상태 변화 과정 자체가 사용자에게 공포와 긴급성을 전달하는 장치입니다.

#### A. State 1: Normal/Baseline (초기 로딩 또는 정상 수치)
*   **조건:** `normalMin` $\le$ `currentValue` $\le$ `normalMax`
*   **시각 효과:** 안정적이고 부드러운 그래프 형태. 색상은 은은한 미스티 블루 계열 (`--color-normal`)을 사용합니다.
*   **애니메이션:** 선형적인(Linear) 움직임으로 Gap이 점진적으로 정상 범위 내에 안착하는 느낌. **"데이터가 안정화되는 중입니다."**라는 톤앤매너를 유지합니다.
*   **Gap 시각화:** 현재 수치가 Normal Range의 중앙값에서 약간 벗어나더라도, 그래프 상에서는 '안전 구역' 안에 머물러 있음을 강조.

#### B. State 2: Warning/Deviation (주의 단계)
*   **조건:** (`currentValue` < `normalMin`) 또는 (`currentValue` > `normalMax`) **AND** `currentValue` $\le$ `criticalThreshold`
*   **시각 효과:** 그래프의 경계선(Boundary Line)이 노란색(`--color-warning`)으로 변하며, 데이터 포인트가 미세하게 떨리는 애니메이션 (Subtle Jitter Effect)이 추가됩니다.
*   **애니메이션:** **"미세한 결함 감지: 시스템 불안정."** 이라는 텍스트와 함께, 그래프의 배경에 잔잔하고 낮은 주파수의 노이즈 패턴(Noise Pattern Overlay)을 적용합니다. (개발팀 가이드: `opacity`를 이용해 깜빡이는 듯한 효과 구현).
*   **Gap 시각화:** Normal Range 바깥쪽으로 벗어난 Gap 부분이 노란색으로 채워지며, '경고' 메시지와 함께 **"평소보다 높은 수치입니다. 생활 습관 점검이 필요합니다."**라는 안내 멘트를 배치합니다.

#### C. State 3: Critical Failure / Defect ID (위협 단계)
*   **조건:** `currentValue` > `criticalThreshold`
*   **시각 효과:** **가장 강력하고 즉각적인 변화.** 전체 컴포넌트 배경의 일부가 강렬한 레드(`--color-critical`)로 깜빡이며, 마치 전원이 꺼지거나 오류 메시지가 뜨는 듯한 시각적 충격을 줍니다.
*   **애니메이션:**
    1.  **Jolt Effect (충격):** 그래프 전체가 X축 또는 Y축 방향으로 순간적으로 짧게 진동합니다.
    2.  **Flashing/Blinking:** Defect ID 값이 표시되는 부분과 배경의 경고 라인이 초당 1~2회 간격을 두고 깜빡입니다. (CSS: `animation-iteration-count: infinite; animation-timing-function: steps(1, 1);`)
    3.  **Warning Text Override:** 기존의 부드러운 문구는 사라지고, **"!!! CRITICAL SYSTEM FAILURE !!!"** 또는 **"Defect ID [XX] 감지: 즉각적인 전문 진단이 필요합니다."**와 같은 경고문구가 중앙에 팝업됩니다.
*   **Gap 시각화:** Gap 자체가 매우 넓게 펼쳐진 직사각형 형태로, 그래프를 압도하며 가장 강한 공포감을 전달합니다.

### 4. 개발 구현 가이드라인 (Actionable Checklist)

1.  **데이터 주입 최우선:** 컴포넌트의 모든 애니메이션과 스타일은 `currentValue`와 세 가지 임계점(Normal/Warning/Critical)을 기준으로 조건부 렌더링되어야 합니다.
2.  **CSS 변수 활용:** 색상, 깜빡임 속도, 진동 강도는 모두 CSS 변수로 관리하여 A/B 테스트 용이성을 확보합니다. (예: `--defect-flash-speed`, `--gap-width`)
3.  **트래킹 통합 지점 명시:** Critical Failure 상태가 활성화되는 순간(State 3 도달), 반드시 **Exit Intent Trigger Point**에 해당하며, 이 시점에 추적 데이터 전송 로직(`trackEvent('Critical_Failure', { metric: metricName })`)이 발동되도록 개발해야 합니다.

import React from 'react';

// 1. Props 정의 (Developer Input Interface) - TypeScript를 이용해 엄격하게 정의합니다.
interface DefectGraphProps {
    metricName: string; // 측정 항목의 이름
    currentValue: number; // 사용자가 측정한 현재 수치
    normalMin: number; // 정상 범위 최소값
    normalMax: number; // 정상 범위 최대값
    criticalThreshold: number; // 임계 실패 기준점 (Critical Failure)
    unit: string; // 단위 표시
}

/**
 * 시스템 오류 시각화 컴포넌트. 
 * 사용자의 현재 수치와 정상 범위 간의 'Defect ID Gap'을 강조합니다.
 */
const DefectIDGraph: React.FC<DefectGraphProps> = ({ 
    metricName, currentValue, normalMin, normalMax, criticalThreshold, unit 
}) => {

    // 2. 상태 로직 (State Logic) - Critical Failure 여부를 판단하는 핵심 로직입니다.
    let status; // 'Normal' | 'Warning' | 'Critical'
    let gapValue = 0; // Gap 계산 값

    if (currentValue >= normalMin && currentValue <= normalMax) {
        status = 'Normal';
        gapValue = 0;
    } else if ((currentValue < normalMin || currentValue > normalMax) && currentValue < criticalThreshold) {
        status = 'Warning';
        // Warning 상태일 때, 정상 범위와의 최소 Gap을 계산하여 경고 수치를 명확히 합니다.
        gapValue = Math.max(Math.abs(normalMin - currentValue), Math.abs(normalMax - currentValue)); 
    } else {
        status = 'Critical';
        // Critical 상태일 때, 임계치 대비 Gap을 계산하여 긴급성을 부여합니다.
        gapValue = Math.abs(criticalThreshold - currentValue); 
    }

    // 3. 스타일링 (Thematic Styling) - Status에 따른 동적 클래스 매핑
    const getStatusStyles = () => {
        switch (status) {
            case 'Normal':
                return "text-green-400 border-green-600 bg-opacity-20";
            case 'Warning':
                return "text-yellow-400 border-yellow-600 bg-opacity-30 animate-pulse"; // 경고 애니메이션 추가
            case 'Critical':
                // 가장 강력하게 인지되도록, 깜빡이는 (flashing) 효과와 진홍색 사용.
                return "text-red-500 border-red-700 bg-[animation-blink_1s_infinite] animate-blink"; 
            default:
                return "text-gray-400 border-gray-600 bg-opacity-10";
        }
    };

    // Tailwind CSS 커스텀 애니메이션 정의 (CSS 파일이나 global style에 필요함)
    // 예시: @keyframes blink { 0%, 100% { opacity: 1; } 50% { opacity: 0.2; } }
    // 이 코드는 컴포넌트 자체에는 포함할 수 없지만, 주석으로 명시하여 개발자가 참고하도록 합니다.

    return (
        <div className="p-8 bg-[#1A3750] rounded-xl shadow-2xl w-full max-w-4xl border-t-4 border-red-700/70">
            <h2 className="text-lg text-gray-300 mb-6 uppercase tracking-widest">🧬 Defect ID Gap Analyzer</h2>

            {/* 1. Header Zone: 측정 항목명과 현재 수치 (가장 강렬하게) */}
            <div className="mb-8 p-6 bg-[#254c7a] rounded-lg border-l-4" style={{ borderColor: getStatusStyles().split(' ')[0].replace('-opacity', '') }}>
                <p className="text-sm font-medium text-gray-300 uppercase tracking-wider">{metricName}</p>
                <div className="flex items-end justify-between mt-2">
                    <span className={`text-7xl font-extrabold transition-all duration-500 ${getStatusStyles().replace('bg', 'text')}`}>
                        {currentValue.toFixed(1)}
                    </span>
                    <span className="text-4xl text-gray-300">{unit}</span>
                </div>
            </div>

            {/* 2. Graph Area: Gap 시각화 (가장 중요한 부분) */}
            <div className="mb-8 p-6 bg-[#1E3750] rounded-lg border border-dashed">
                <p className="text-sm text-gray-400 mb-4">정상 범위 대비 결함 Gap 시각화:</p>
                
                {/* 가상의 그래프 라인 */}
                <div className="relative h-12 flex items-end justify-between py-3 border-b border-gray-600">
                    
                    {/* 정상 범위 (Normal Range - 기준선) */}
                    <div 
                        className={`absolute bottom-0 left-[${((normalMin / normalMax) * 80 + 10)}%] w-[${(((normalMax - normalMin) / normalMax) * 60)}%] h-2 rounded ${status === 'Normal' ? 'bg-green-500/70' : 'bg-gray-600'} transition duration-700`}
                        style={{ left: `${(normalMin / (normalMin + normalMax) * 100)}%`, width: `${((normalMax - normalMin) / (normalMin + normalMax)) * 100}%` }}
                    ></div>

                    {/* 현재 값 포인터 */}
                    <div 
                        className={`w-6 h-6 rounded-full ${getStatusStyles().replace('bg', 'bg')}`} 
                        style={{ bottom: `${currentValue}px`, left: `calc(10% + ${(Math.abs(normalMin - normalMax) / (2 * Math.max(normalMin, normalMax)))}*100%)` }} // 위치 계산은 복잡하므로 임시로 설정
                    ></div>

                    {/* Critical Threshold 표시 */}
                    <div 
                        className={`absolute bottom-0 w-px h-full ${status === 'Critical' ? 'bg-red-600 animate-pulse' : 'bg-gray-700 opacity-50'}`}
                        style={{ left: `calc(${((criticalThreshold / (normalMin + normalMax)) * 100)}%)` }}
                    ></div>

                </div>
            </div>

            {/* 3. Footer CTA Zone */}
            <div className="flex justify-between items-center pt-4 border-t border-gray-700">
                 <p className="text-sm text-gray-400">현재 Defect ID Gap: <span className={`font-bold ${status === 'Critical' ? 'text-red-500' : 'text-yellow-500'}`}>{gapValue.toFixed(1)} {unit}</span></p>
                <button 
                    className="px-6 py-3 bg-red-700 hover:bg-red-800 text-white font-semibold rounded transition duration-200 cursor-pointer shadow-lg transform hover:scale-[1.02]"
                >
                    전문 진단 및 맞춤 솔루션 받기 (Exit Intent) 🚀
                </button>
            </div>

        </div>
    );
};

export default DefectIDGraph;

CTA는 단순히 "구매하기"가 아닌, **'개인화된 다음 단계의 행동 유도'**여야 합니다.

2.  **Standard Tier CTA:**

3.  **Premium Tier CTA:**
    *   **문구 예시:** "최종 Gap 리스크 진단 및 1:1 전문가 연계 받기"

## 2. 핵심 API 엔드포인트 설계 (The Data Pipeline)
진행 과정에서 발생하는 모든 상태 변화와 데이터를 처리할 메인 진단 흐름을 정의합니다.

### A. [Step 1] 사용자 입력 및 초기 진단 요청
*   **Endpoint:** `POST /api/v1/diagnose/initial`
*   **Body (Request):** `{ "user_id": "uuid", "session_token": "jwt_token", "input_data": { "hba1c": 6.5, "blood_pressure": "130/85", "lifestyle_score": 7 } }`
*   **Response:** `{ "status": "SUCCESS", "severity_index": 0.65, "recommended_funnel_state": "Basic" }`

### B. [Step 2] Gap 수치 분석 및 위험도 출력 (Core Logic)
이 부분이 가장 중요합니다. 단순히 점수를 주는 것이 아니라, **'어떤 Gap 때문에 어떤 상품을 써야 하는지'**를 결정해야 합니다.
*   **Endpoint:** `POST /api/v1/diagnose/calculate`
*   **Body (Request):** `{ "user_id": "uuid", "session_token": "jwt_token", "input_data": { ... } }`
*   **Logic Flow:**
    1.  DB에서 `Gap Matrix`를 조회합니다.
    2.  입력 데이터와 매트릭스를 비교하여 **'Critical Gap (임계점 초과)'** 리스트를 추출합니다.
    3.  추출된 Gap들의 심각도(Severity)에 따라 0~1 사이의 단일 `severity_index`를 계산합니다.
    4.  이 인덱스에 따라 Basic/Standard/Premium을 결정하고, 해당 근거 (예: "수면 부족 Gap으로 인해 Standard 패키지가 필요합니다.")를 반환합니다.

### C. [Step 3] 상품 정보 조회 및 최종 CTA 요청
*   **Endpoint:** `GET /api/v1/product/{tier}`
*   **Parameters:** `{ tier: "Standard" }`
*   **Response:** 해당 티어의 상세 구성, 가격, 기대 효능 등의 정적(Static) 데이터를 반환합니다.

## 3. 사용자 인증 및 세션 관리 (Authentication & Resilience)
진단 과정은 여러 단계에 걸치므로, 사용자가 이탈했다가 돌아와도 **'현재까지 진단된 Gap 수치'**를 기억해야 합니다.

1.  **인증 방식:** JWT(JSON Web Token) 기반의 Stateless 인증을 채택합니다. (매 요청마다 토큰 검증).
2.  **세션 관리:** `Funnel State` 테이블 (DB에 신설): 사용자 ID, 마지막 진단 시점, **현재 Gap Score Snapshot**, 현재 Funnel Step(0~4), 그리고 다음 예상 CTA를 저장합니다.
3.  **Gap 처리 로직의 안정성:** 모든 API 호출은 트랜잭션으로 묶여야 합니다. 만약 결제 실패 등으로 인해 세션이 끊기더라도, `Funnel State`에 기록된 정보를 통해 **'어디까지 진행했는지'를 보여주며 재진입(Re-entry)** 할 수 있도록 설계합니다.

## 4. 결제 시스템 연동 구조 (Payment Integration)
결제는 가장 오류가 많이 발생하는 지점이므로, '최소한의 시도'와 '자동 복구 로직'에 집중해야 합니다.

*   **PG사 선택:** 초기 테스트 단계에서는 **Stripe Checkout Session**을 활용하는 것이 가장 빠르고 글로벌 표준화되어 있습니다. (국내 PG사는 별도의 웹훅(Webhook) 처리가 필수적입니다.)
*   **핵심 구조: Webhook 기반 트랜잭션 검증:**
    1.  사용자가 결제 버튼 클릭 $\rightarrow$ FE가 Stripe Checkout URL로 리다이렉트.
    2.  Stripe는 PG사 게이트웨이를 통해 결제를 처리하고, **성공/실패 상태를 다시 Backend API의 Webhook 엔드포인트(`POST /api/v1/webhooks/payment`)로 전송**합니다. (클라이언트 측 실패에 의존하지 않음).
    3.  Backend는 이 웹훅을 받아 DB의 해당 `Funnel State`와 연동하여 **'구매 완료 플래그(Purchased Flag)'**를 업데이트하고, 상품 활성화 로직을 트리거 합니다.
